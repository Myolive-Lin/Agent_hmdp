# 第 5 课：达人探店

> 迭代 4｜参考 `dianping`：MySQL 保存博客和点赞计数，Redis ZSet 保存点赞用户及时间顺序。

## 本课接口

- `POST /blog`：发布探店笔记。
- `GET /blog/{id}`：查询博客详情。
- `GET /blog/hot?current=1`：热门博客分页。
- `GET /blog/of/user?id=...&current=1`：指定用户博客。
- `PUT /blog/like/{id}`：点赞/取消点赞切换。
- `GET /blog/likes/{id}`：最早点赞的 5 个用户。
- `POST /upload/blog`：上传博客图片。

## 任务 1：基础结构

创建 Blog、BlogMapper、IBlogService、BlogServiceImpl、BlogController。Blog 使用最终 Lombok，并与 `tb_blog` 字段对应。

发布时从 UserHolder 获取 userId，不能使用前端传入的作者 ID：

```java
UserDTO user = UserHolder.getUser();
blog.setUserId(user.getId());
save(blog);
```

返回保存后的 blogId。发布、点赞和上传接口需要登录。

## 任务 2：详情和热榜

详情流程：

1. 根据 id 查询 Blog。
2. 不存在返回错误。
3. 查询作者并补充 nickName、icon。
4. 当前已登录时，从 Redis 查询是否点赞并设置 isLike。

热榜按 liked 降序分页，建议再按 id 降序保证相同点赞数下顺序稳定。批量收集一页 userId 查询用户，避免每篇博客单独访问一次数据库。

## 任务 3：ZSet 点赞

Redis key：

```java
public static final String BLOG_LIKED_KEY = "blog:liked:";
```

完整 key：`blog:liked:{blogId}`。

- member：userId。
- score：首次点赞时的 `System.currentTimeMillis()`。

处理流程：

```text
ZSCORE 查询当前用户
  不存在 → MySQL liked + 1 → ZADD userId timestamp
  已存在 → MySQL liked - 1 → ZREM userId
```

只有 MySQL 更新成功后才修改 Redis。取消点赞的 SQL 增加 `liked > 0` 条件，避免计数小于 0。

该接口是“切换状态”，同一请求重复发送会产生相反结果；前端必须避免自动重复提交。当前按参考项目学习，不额外增加点赞关系表。

## 任务 4：点赞榜

```java
Set<String> top5 = stringRedisTemplate.opsForZSet()
        .range(BLOG_LIKED_KEY + blogId, 0, 4);
```

ZSet 按 score 从小到大返回最早点赞用户。将 ID 批量查询为 UserDTO，并按照 Redis 返回的 ID 顺序恢复结果。

参考项目中 SQL 保序可使用：

```sql
ORDER BY FIELD(id, ...)
```

拼接 ID 前必须确认全部来自解析成功的 Long；也可以在 Java 中使用 Map 恢复顺序。

## 任务 5：图片上传

参考 UploadController 完成上传：

1. 限制 JPEG/PNG 和文件大小。
2. 服务端生成随机文件名，不能直接使用用户文件名作为保存路径。
3. 保存路径来自 application 配置。
4. 返回前端可访问的相对路径，不返回本机绝对路径。

## 当前实现边界

MySQL 点赞计数与 Redis 点赞关系是两次写入，某一次失败可能造成不一致。当前先掌握参考项目的 ZSet 方案，通过测试和人工检查发现异常；事务消息和完整对账系统留到项目强化阶段。

## 完成标准

- [ ] 发布者只能是当前登录用户。
- [ ] 详情、热榜和用户博客可查询。
- [ ] 已登录/未登录时 isLike 正确。
- [ ] 点赞后计数增加并写 ZSet；取消后计数减少并移除。
- [ ] 最早 5 名用户顺序正确。
- [ ] 文件类型、大小和保存路径经过检查。
